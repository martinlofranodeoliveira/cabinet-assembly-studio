# Cabinet Assembly Studio

Development **0.1.0**, by [Lofrano Tecnologia](https://lofranotecnologia.com.br). An original MIT React + TypeScript application for inspecting a five-panel, open-front cabinet concept. Real Three.js boxes are rendered through React Three Fiber; the same accepted parameters also drive the BOM, exact 2D projections and exports.

This is not a cutting, CNC, joinery, structural or fabrication tool. No physical suitability is inferred.

## Install and run

Use Node 22 and npm. The dependency versions in `package.json` are exact. The included `package-lock.json` is generated by npm from the exact manifest; retain it for reproducible `npm ci` installs. Dependency updates require deliberate lock regeneration and review.

```sh
npm ci
npm run dev
npm test
npm run demo -- --assert
npm run demo -- --assert --json
npm run build
VITE_BASE_PATH=/cabinet-assembly-studio/ npm run build
```

Open the local address printed by Vite. The static output is `dist/`. Its JS, CSS, fonts and geometry need no runtime CDN, account, API or external model. After installation/build, a local static server can serve it without Internet access. This does not install a service worker or promise offline reload of an uncached hosted page. No deployment workflow is included.

Example human-readable demo output, specified by the CLI:

```text
Cabinet Assembly Studio — development 0.1.0
5 panels · clear W/H/depth: 564 / 764 / 382 mm
Panel volume: 22226976 mm³
Explosion 1: gap 160 mm; bounds [-160,-160,0] → [760,960,548] mm
Concept only — not a fabrication plan.
Demo assertions completed.
```

The `--json` variant emits one JSON object after the npm/build command messages; to consume only that object after the demo has compiled, run `node build/tests/cli.mjs --assert --json`.

## Work with a concept

The interface starts in Portuguese. Choose **English** in **Idioma** to switch all controls, errors and operating messages. Locale does not alter geometry, undo history, saved concepts or JSON.

1. Select **Fundo / Back** in the panel list or click a mesh. The inspector reports `564 × 764 × 6 mm` for the default back.
2. Edit a complete dimension draft and press **Apply dimensions**. Setting `W=720` produces clear width `684 mm` with the other defaults. Until Apply succeeds, the scene and exports retain the previous model.
3. Enter `W=36`, `t=18` to see a cross-field error as well as the range diagnostic. Undo/redo retain up to 20 accepted edits.
4. Move the explosion slider. It translates panels without changing nominal measurements or exports. Front, isometric and Fit are explicit camera commands.
5. Camera navigation starts **off**. Enter **Navigate in 3D** to orbit/zoom; exit with its button or Escape. Controls are disconnected on exit and the actual canvas touch action is restored to `pan-y`.
6. **Save copy** creates a new named concept locally. The counter shows the ten-concept limit. Select a saved concept to load or rename it, or use **Update selected** to replace its dimensions with the currently applied dimensions while keeping its saved name. **Remove saved** asks for confirmation and deletes only that saved copy; the open work stays intact. Removing a copy frees a slot. Unapplied dimension drafts are never saved. Storage failure does not prevent editing or exporting.
7. Import a bounded schema-1 JSON file or export deterministic JSON/SVG. SVG is a labelled nominal panel layout, **not a nesting/cutting plan**.

Without WebGL2, after context loss, or on a scene error, the precise projections and all DOM operations remain available. Use Retry 3D to attempt a new context. On mobile, Object, Properties and 2D plan buttons select the control section below the viewport. Measurements are not tiny canvas labels.

## Core usage

The pure core is also used by the bundled CLI:

```ts
import { concept, defaults, derive, exportJSON } from './src/core';
const c = concept('Synthetic 720', { ...defaults, W: 720 });
const geometry = derive(c.parameters);
console.log(geometry.clearWidth); // 684
const json = exportJSON(c);
```

Use `concept`, `parameters` or `importJSON` at trust boundaries; `derive` and `display` expect already accepted parameters. Imports never trust cached geometry. See [the precise contract](docs/contract.md), [design rationale](docs/design.md) and [source review record](DESIGN.md).

## Verification and limits

`npm test` runs strict TypeScript, independent literal and exhaustive cell-occupancy math tests, adversarial/transactional state tests, actual ReactDOM interactions in an isolated JSDOM VM, actual R3F scene-object tests, and a production subpath build with asset/comment assertions. Tests compile before execution and use Node's test runner. The separate demo asserts literal default results independently.

These tests do **not** demonstrate real GPU rendering, browser gestures, pointer hit accuracy, responsive appearance or accessibility conformance. A browser host was unavailable; real WebGL, responsive, keyboard/screen-reader and visual review remain unverified.

Resource limits: five box meshes, demand rendering, DPR 1–1.5, no texture/environment/model downloads, bounded history, imports and local storage. JSON is byte-bounded before decoding, not an RSS or pre-decoder recursion sandbox. Local persistence is single-tab/last-write-wins and is not a backup. No arbitrary code/mesh import, telemetry, hardware, tolerances, density, price or structural calculation is included.
